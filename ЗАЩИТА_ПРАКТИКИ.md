## ВВЕДЕНИЕ И НАЗНАЧЕНИЕ {#введение}

### Описание проекта

**БГИТУ Афиша** — это комплексная веб-платформа, разработанная для упрощения процесса создания, публикации и управления мероприятиями в Брянском государственном инженерно-технологическом университете. 

Платформа предоставляет студентам удобный способ узнавать о предстоящих событиях, регистрироваться на них и отслеживать свою историю участий. Администраторам платформа даёт мощные инструменты для управления событиями, импорта данных студентов, аналитики и формирования отчётов.

### Актуальность

В современных университетах огромное количество мероприятий: концерты, лекции, конкурсы, волонтёрские акции, мастер-классы. Студентам сложно отслеживать все события, а администраторам трудно координировать всех участников и анализировать эффективность мероприятий. БГИТУ Афиша решает эту проблему, централизуя всю информацию о событиях в одном месте и предоставляя интегрированную систему управления.

## ЦЕЛИ И ЗАДАЧИ ПРОЕКТА {#цели}

### Основные цели

1. **Централизованное управление мероприятиями** — создать единую платформу для хранения и публикации всех событий университета
2. **Упрощение регистрации студентов** — обеспечить простой и быстрый процесс регистрации на события через социальные сети (ВКонтакте)
3. **Система уведомлений** — информировать студентов о новых событиях и изменениях в расписании мероприятий
4. **Аналитика и отчётность** — предоставить администраторам инструменты для анализа посещаемости, популярности событий и активности студентов
5. **Управление доступом** — реализовать систему ролей для разделения прав между администраторами, модераторами и студентами

### Решаемые задачи

1. **Аутентификация через VKontakte** — интеграция OAuth 2.0 с ВКонтакте для безопасной аутентификации без необходимости запоминания пароля
2. **Управление профилями студентов** — хранение информации о студентах (факультет, группа, курс поступления)
3. **CRUD операции над событиями** — создание, редактирование, удаление и просмотр мероприятий
4. **Система категоризации** — классификация событий по 8 категориям (концерты, внутренние активности, публичные события, конкурсы, лекции, мастер-классы, волонтёрство, новости)
5. **Регистрация и управление участниками** — отслеживание зарегистрированных на событие студентов и фактической явки
6. **Импорт данных из Excel** — загрузка списков студентов, событий и новостей в массовом порядке
7. **Экспорт данных** — выгрузка информации о участниках в формате Excel
8. **Многоканальная рассылка** — отправка уведомлений через in-app, Email и ВКонтакте
9. **Система аудита** — логирование всех критических действий администраторов и модераторов
10. **Отчётность по событиям** — создание подробных отчётов о проведённых мероприятиях с указанием активных участников

- Server Components для оптимизации
- Клиентские компоненты для интерактивности

**Слой 2: API Routes**
- Next.js API routes для REST endpoints
- Валидация входных данных (Zod)
- Обработка ошибок и логирование

**Слой 3: Бизнес-логика (Services)**
- Изолированные функции для работы с событиями

- Уведомления

- Типизированные запросы к БД

- **SOLID принципы**: единственная ответственность, открытость/закрытость

- **REST API**: стандартные HTTP методы (GET, POST, PUT, DELETE)
- **Server-first**: использование Server Components для улучшения производительности
- **Type Safety**: полная типизация через TypeScript

## ОСНОВНЫЕ КОМПОНЕНТЫ И ФУНКЦИОНАЛЬНОСТЬ {#компоненты}

### 1. Система аутентификации и авторизации

#### Интеграция ВКонтакте (VK OAuth 2.0)

Аутентификация реализована через **NextAuth.js** с поддержкой OAuth 2.0 от ВКонтакте:

```
Пользователь → Клик "Вход через VK" → Редирект на VK OAuth
                                       ↓
                                VK запрашивает разрешение
                                       ↓
                                Пользователь разрешает
                                       ↓
                        VK отправляет токен в приложение
                                       ↓
                        Создание/обновление User в БД
                                       ↓
                        Установка сессии
                                       ↓
                        Редирект на главную страницу
```

**Процесс регистрации нового пользователя:**
1. Пользователь переходит на страницу логина
2. Нажимает кнопку "Вход через ВКонтакте"
3. Перенаправляется на OAuth сервер VK
4. После авторизации система получает:
   - VK ID пользователя
   - Имя
   - Фотографию профиля
5. Автоматически создаётся аккаунт пользователя
6. Предлагается заполнить профиль (факультет, группа)
7. Пользователь попадает на главную страницу

**Роли и права доступа:**
- Система использует поле `role` для определения прав
- Доступ к админ-панели: только пользователи с ролью `ADMIN`
- Доступ к редактированию события: только автор или модератор
- Студенты имеют ограниченный доступ только для просмотра и регистрации

#### Управление сессиями

- Сессии хранятся в таблице `Session` в БД
- Токены подписаны секретом `NEXTAUTH_SECRET`
- Время жизни сессии настраивается в конфиге NextAuth
- При выходе сессия удаляется из БД

### 2. Управление событиями

#### Создание события

**Поля события:**
- Название (title)
- Категория (category) — выбор из 8 категорий
- Дата и время (date, time)
- Продолжительность (duration)
- Место проведения (location)
- Описание (description)
- Максимальное кол-во участников (maxParticipants)
- Фотографии (images)
- Ответственный (responsible)
- Контакт (contact)
- Требуется ли одобрение (requiresApproval)
- Видимость события (isPublic)

**Права на создание:**
- TEACHER, MODERATOR, ADMIN могут создавать события
- События автоматически становятся черновиками
- Администратор может опубликовать событие

#### Регистрация на событие

**Workflow:**

```
Студент просматривает событие
         ↓
Клик на "Зарегистрироваться"
         ↓
Проверка:
  ✓ Есть ли свободные места?
  ✓ Уже ли зарегистрирован?
  ✓ Требуется ли одобрение?
         ↓
Создание записи EventParticipant
  status = PENDING или CONFIRMED
         ↓
Рассылка уведомления
         ↓
Обновление счётчика участников
```

**Статусы участия:**
- **PENDING** — ожидает одобрения модератором (если requiresApproval=true)
- **CONFIRMED** — участник подтвержден

#### Отметка явки

Администратор или модератор может отметить, что студент пришёл на событие:
- Изменение status на CONFIRMED
- Автоматическое обновление статистики
- Логирование действия в аудит-лог

#### Экспорт участников

Администратор может выгрузить список участников события в Excel:
- ФИО, Email, Группа
- Статус (PENDING / CONFIRMED)
- Дата регистрации

### 3. Система уведомлений

#### Многоканальная доставка

Уведомления могут отправляться через:

1. **In-App** — уведомления внутри приложения
   - Отображаются в центре уведомлений
   - Помечаются как прочитанные при открытии
   - История хранится в таблице Notification

2. **Email** — через Yandex (опционально)
   - Интеграция с Yandex для отправки писем
   - Шаблоны уведомлений

3. **ВКонтакте** — прямые сообщения в VK
   - Интеграция с VK API
   - Отправка уведомлений подписчикам

#### Типы уведомлений

| Тип | Описание |
|-----|---------|
| **NEW** | Новое событие в выбранной категории |
| **CHANGE** | Изменение в событии, на которое зарегистрирован |
| **COMPLETE** | Событие завершено |
| **EVENT** | Общее событие |
| **SYSTEM** | Системные уведомления |
| **IMPORT_COMPLETED** | Импорт данных завершён |

#### Управление подписками

Пользователи могут управлять своими уведомлениями:

```
Профиль → Настройки уведомлений
  ├─ Уведомлять о новых событиях ☑
  ├─ Уведомлять об изменениях ☑
  ├─ Уведомлять о новостях ☐
  ├─ Канал: In-App ☑
  ├─ Канал: Email ☐
  └─ Канал: VK ☐

Категории для подписки:
  ☑ Концерты

  ☐ Лекции
  ☐ Волонтёрство
```

### 4. Импорт и экспорт данных

#### Импорт студентов из Excel

**Формат файла:**
```
| ФИО | Email | Факультет | Группа | Курс поступления |
|-----|-------|-----------|--------|-----------------|
| Иван Петров | ivan@bgitu.ru | ИТ | ПМ-21 | 2021 |
| Мария Сидорова | maria@bgitu.ru | МЕХ | МЕ-21 | 2021 |
```

**Процесс импорта:**
1. Администратор загружает Excel файл
2. Система парсит данные (XLSX)
3. Валидирует каждую строку:
   - Email не дублируется
   - Требуемые поля заполнены
   - Формат Email корректен
4. Создаёт новые аккаунты пользователей
5. Генерирует отчёт:
   - Создано: N строк
   - Обновлено: M строк
   - Ошибок: K строк
5. Логирует действие в аудит-лог

#### Экспорт участников события

Выгрузка списка участников в Excel:
- Полная информация: ФИО, Email, Факультет, Группа
- Статус участия
- Дата регистрации

#### Импорт новостей из Excel

Администраторы могут импортировать новости и объявления для массовой рассылки.

### 5. Админ-панель

#### Главный дашборд

Администратор видит:

**KPI Метрики:**
- Всего пользователей в системе
- Активных пользователей (за неделю/месяц)
- Всего событий
- Предстоящих событий
- Завершённых событий
- Средняя явка (%)

**Графики:**
1. Распределение событий по категориям (круговая диаграмма)
2. Динамика регистраций за период (линейный график)
3. Явка vs регистрации по событиям (столбчатая диаграмма)
4. Топ-10 популярных событий (ранжированная таблица)
5. Активность по дням недели (столбчатая диаграмма)
6. Активность пользователей (таблица с рейтингом)

#### Управление событиями

**Таблица событий:**
- Список всех событий с фильтрацией
- Фильтры: категория, дата, статус
- Действия: редактировать, удалить, экспортировать участников
- Просмотр детальной статистики каждого события

#### Управление пользователями

**Таблица пользователей:**
- Поиск по ФИО, Email
- Просмотр профиля
- Редактирование роли
- Просмотр истории событий
- Удаление аккаунта (с предупреждением)

#### Аудит-логи

**История всех операций:**
- Кто (User)
- Что (Action: CREATE, UPDATE, DELETE)
- Когда (DateTime)
- Что изменилось (Metadata: старые/новые значения)
- IP адрес и User Agent

### 6. Календарь и навигация

#### Интерактивный календарь

- Месячный вид с событиями
- Клик на дату показывает события этого дня
- Цветовая кодировка по категориям
- Навигация между месяцами

#### Список событий с фильтрацией

- Фильтр по категориям (мультиселект)
- Сортировка по дате, популярности
- Отображение статуса события
- Быстрые кнопки: зарегистрироваться, просмотр, отмена

### 7. Профиль пользователя

**Общая информация:**
- Аватар (из VK)
- ФИО
- Email
- Факультет и группа
- Год поступления
- Био (о себе)

**История событий:**
- Список всех зарегистрированных событий
- Фильтр по статусу
- Фильтр по периоду

**Настройки:**
- Уведомления (какие каналы, какие типы)
- Приватность
- Согласие с политикой конфиденциальности

### 8. Система отчётов о событиях

После завершения события администратор может создать отчёт:

**Содержание отчёта:**
- Краткое резюме события
- Список выполненных задач
- Фотографии с события
- Список активных участников
- Комментарии организатора
- Статус: DRAFT или PUBLISHED

**Workflow:**
```
Событие завершено
     ↓
Админ создаёт отчёт (DRAFT)
     ↓
Редактирует и добавляет фото
     ↓
Публикует отчёт (PUBLISHED)
     ↓
Отчёт видим в истории события
     ↓
Рассылается уведомление участникам
```

### Метрики администратора

Система собирает и анализирует следующие метрики:

#### 1. Метрики событий

| Метрика | Описание | Формула |
|---------|---------|---------|
| **Явка** | Процент пришедших от зарегистрированных | (Confirmed / Registered) × 100% |
| **Популярность** | Количество просмотров события | SUM(views) |
| **Спрос** | Количество регистраций | COUNT(EventParticipant) |
| **Заполнение** | Процент занятых мест | (Current / Max) × 100% |

#### 2. Метрики пользователей

| Метрика | Описание |
|---------|---------|
| **Активные пользователи** | Пользователи, совершившие действие за период |
| **Новые пользователи** | Зарегистрированы за период |
| **Средняя активность** | Среднее количество действий на пользователя |

#### 3. Метрики системы

| Метрика | Описание |
|---------|---------|
| **Трафик сайта** | Уникальные входы в день |
| **Операции** | Выполненные действия (регистрации, просмотры) |

## БЕЗОПАСНОСТЬ И АУДИТ {#безопасность}

### Система безопасности

#### 1. Аутентификация

- **OAuth 2.0 через ВКонтакте** — безопасная аутентификация без передачи пароля
- **Сессии** — управление через NextAuth.js с безопасными cookie
- **HTTPS** — все соединения зашифрованы (обязательно в продакшене)

#### 2. Авторизация

**Модель ролей:**
```
┌─────────────────────────────────────┐
│         PERMISSION MATRIX           │
├──────────┬──────┬──────┬────┬───────┤
│ Action   │Student│Teacher│Mod │ Admin│
├──────────┼──────┼──────┼────┼───────┤
│View Event│  ✓   │  ✓   │ ✓  │  ✓   │
│Create    │  ✗   │  ✓   │ ✓  │  ✓   │
│Edit Own  │  ✗   │  ✓   │ ✓  │  ✓   │
│Edit All  │  ✗   │  ✗   │ ✗  │  ✓   │
│Delete    │  ✗   │  ✗   │ ✗  │  ✓   │
│Admin Pan │  ✗   │  ✗   │ ✗  │  ✓   │
│Import    │  ✗   │  ✗   │ ✗  │  ✓   │
└──────────┴──────┴──────┴────┴───────┘
```

#### 3. Валидация данных

Все входные данные валидируются через **Zod** схемы:

```typescript
// Пример: CreateEventSchema
EventSchema = z.object({
  title: z.string().min(3).max(255),
  category: z.enum([CONCERT, LECTURE, ...]),
  date: z.date().min(now()),
  maxParticipants: z.number().positive(),
  description: z.string().max(5000),
})
```

**Защита от:**
- SQL Injection — через Prisma ORM (параметризованные запросы)
- XSS — React автоматически экранирует данные
- CSRF — NextAuth защищает от CSRF токенами

#### 4. Аудит и логирование

**Все критические действия логируются:**

```
Action Types:
├─ CREATE_EVENT
├─ UPDATE_EVENT
├─ DELETE_EVENT
├─ REGISTER_PARTICIPANT
├─ CONFIRM_PARTICIPANT
├─ CREATE_ADMIN
├─ IMPORT_USERS
├─ EXPORT_DATA
├─ DELETE_USER
└─ LOGIN/LOGOUT

Каждый лог содержит:
├─ Actor ID (кто сделал)
├─ Action (что сделал)
├─ Entity Type & ID (на что сделал)
├─ Metadata (старые/новые значения)
├─ IP адрес
├─ User Agent
└─ Timestamp
```

**Использование:**
- Обнаружение аномалий
- Судебное разбирательство
- Анализ нарушений
- Восстановление данных

#### 5. Защита конфиденциальности

**Управление согласием:**
- ✓ Согласие с политикой конфиденциальности
- ✓ Согласие с условиями использования
- ✓ Версионирование документов
- ✓ Отслеживание даты согласия

**Ограничение видимости данных:**
- Студенты видят только основную информацию друг друга
- Email видно только администраторам
- Списки участников ограничены по доступу

## МАСШТАБИРУЕМОСТЬ И ПРОИЗВОДИТЕЛЬНОСТЬ {#масштабируемость}

### Архитектура для масштабирования

#### 1. База данных

**Оптимизация:**
- Индексы на часто используемые поля (date, category, status)
- Денормализация для быстрых запросов (currentParticipants)
- Кэширование часто запрашиваемых данных

```sql
CREATE INDEX idx_event_date ON Event(date);
CREATE INDEX idx_event_category ON Event(category);
CREATE INDEX idx_participant_event_status ON EventParticipant(eventId, status);
CREATE INDEX idx_user_role ON User(role);
```

**Масштабирование:**
- PostgreSQL поддерживает горизонтальное масштабирование через реплики
- Кэширование запросов через Redis (если требуется)
- Архивирование старых событий

#### 2. Backend

**Next.js Server Components:**
- Выполняются на сервере (нет отправки JS клиенту)
- Уменьшают размер бандла
- Улучшают производительность

**API Optimization:**
- Pagination для больших списков
- Выборка только необходимых полей
- Кэширование ответов (Cache-Control headers)

#### 3. Frontend

**Оптимизация производительности:**
- React 19 Compiler для автоматизированной оптимизации
- Lazy loading компонентов
- Image optimization для фотографий событий
- Minification и compression

**Метрики производительности:**
- First Contentful Paint (FCP) < 1.5s
- Largest Contentful Paint (LCP) < 2.5s
- Cumulative Layout Shift (CLS) < 0.1

#### 4. Развёртывание

**Vercel Deployment:**
- CDN по всему миру
- Автоматическое масштабирование
- Edge functions для глобально распределённых операций
- Кэширование на Edge

Проект может служить основой как для локального использования в БГИТУ, так и для расширения на другие учебные заведения, став полноценной SaaS платформой.
